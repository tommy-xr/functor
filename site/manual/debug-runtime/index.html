Debug automation

Functor can capture a fixed pose, replay gameplay frame by frame, or let an external script inspect and drive a running game. All three use the native runner; game logic remains the same interpreted .fun source you run interactively.

This page is the practical path. The exhaustive debug runtime contract is published from the repository documentation at a stable Markdown URL, including every endpoint, payload, status code, model encoding, XR shape, and project-sync route.

Choose a deterministic workflow

GoalClockCapture
One authored pose or animation time --fixed-time T pins every frame to tts = T and dts = 0 --capture-frame out.png
Gameplay after reproducible input --input-script advances by a fixed --script-dt per rendered frame --capture-at-frame N --capture-frame out.png

These modes are intentionally incompatible. --fixed-time is a zero-delta pin; an input script must advance the simulation. The CLI rejects --fixed-time together with --input-script. 

# static pose at tts = 3 seconds
functor -d examples/hello run native \
  --fixed-time 3 --capture-frame pose.png --capture-size 1280x720

Use the HTTP workflow when a driver needs to read the model between actions, inject pointer motion, or choose its next input from the previous result.

Scripted input and capture

An input file has one <frame> <control> <down|up> event per line. Events run before that zero-based frame's tick. 

# actions.input
0  Right       down
2  2           down     # digits are bare: 2, not Num2
3  2           up
4  Mouse.Left  down     # Mouse. is required for buttons
28 Mouse.Left  up
40 Right       up

Key names are case-insensitive: letters, Up/Down/ Left/Right, Space, Enter, Escape, and bare digits 0–9. A bare Left is the arrow key, so mouse buttons use Mouse.Left, Mouse.Right, or Mouse.Middle. Pointer motion is available through HTTP injection, not input-script lines. 

functor -d examples/hello run native \
  --input-script actions.input --script-dt 0.016666667 \
  --capture-at-frame 120 --capture-frame scripted.png \
  --capture-size 1280x720

--capture-at-frame requires --capture-frame and is meaningful only with --input-script. --capture-frame implies a hidden GL window, so the run does not steal focus or capture the cursor.

Drive a hidden debug server

Start with a hidden window when you need PNG captures. Use --headless instead when model and scene JSON are enough; headless mode has no pixels, so POST /capture returns 503. 

functor -d examples/hello run native --debug-port 8077 --hidden

The server binds 127.0.0.1 by default and has no authentication. Do not use --debug-bind 0.0.0.0 unless the network is trusted. 

H=http://127.0.0.1:8077

# Pin a movable clock. Do not launch with --fixed-time.
curl -s -X POST "$H/time" -d '{"type":"set","tts":0}'

# Keyboard, mouse button, and pointer motion use separate input payloads.
curl -s -X POST "$H/input" -d '{"type":"key","key":"2","down":true}'
curl -s -X POST "$H/input" -d '{"type":"mouse_button","button":"left","down":true}'
curl -s -X POST "$H/input" -d '{"type":"mouse_move","x":320,"y":180}'

# Queue four fixed steps. The response acknowledges the queue, not completion.
curl -s -X POST "$H/time" -d '{"type":"advance","dts":0.016,"frames":4}'
until [ "$(curl -s "$H/state" | jq .pending_steps)" -eq 0 ]; do :; done

curl -s "$H/state" | jq '{frame, tts, model}'
curl -s -X POST "$H/capture" -o step.png

# Release held controls before the next sequence.
curl -s -X POST "$H/input" -d '{"type":"key","key":"2","down":false}'
curl -s -X POST "$H/input" -d '{"type":"mouse_button","button":"left","down":false}'

For input-dependent steps, advance one frame and wait after each action. Batches can drain up to eight simulation steps per rendered frame, while input and network I/O are serviced per rendered frame. Always poll pending_steps back to 0 before treating a batch as settled.

POST /time returns 409 Conflict under --fixed-time. To begin at a known time and then step, omit that flag and send {"type":"set","tts":T}.

Endpoint map

GET / returns the runtime's own discoverable route index.

RouteUse
GET /stateframe, time, pending steps, input, structured model, and views
GET /scenecamera, scene, and lights as JSON
POST /capturethe next rendered frame as image/png
POST /inputkeyboard, pointer, mouse button, wheel, UI, and desktop XR injection
POST /timepause, advance one or many steps, or resume wall clock
POST /reload-sourcevalidate and hot-swap one entry source with the model preserved
GET /projectread the running project's own sibling .fun sources

Project-wide reload, asset sync, rewind, traces, Quest forwarding, and the exact JSON schemas are in the full Markdown contract.

Find frame_stats telemetry

Run native with the global --json flag and filter the newline-delimited event stream. frame_stats is emitted once per 300-frame averaging window, not on every frame. 

functor --json -d examples/lighting run native \
  | jq 'select(.type == "frame_stats")'

The event separates interpreter tick_us/draw_us from native GL render_us/swap_us, and includes total frame_us, budget_pct, the averaging over_n_frames, and optional GPU resource counters. See the published CLI output contract for the full schema and renderer behavior.

Debug HTTP is also available through the typed TypeScript SDK in tools/functor-sdk and the functor mcp server.
